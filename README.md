# saby-mcp-ro

MCP-сервер для **чтения** данных Saby (СБИС) из ИИ-ассистента.

Документы и этапы, задачи, контрагенты, подразделения, организации,
сертификаты, МЧД. 22 команды чтения, 6 инструментов.

**Команды, которые меняют данные, здесь не просто запрещены — их нет.**
Ни в каталоге, ни в инструментах, ни в коде на провод. Исполнителя не
существует, поэтому подтверждать нечего.

## Состояние

Проверено живыми вызовами на боевой сессии, не по справке:

| | |
|---|---|
| команд в каталоге | 22 |
| вернули живые данные | **15** |
| требуют настоящих данных или лицензии | 7 |
| падений, ошибок, зависаний | **0** |
| типов документов в справочнике | 59, из них **32 проверено живыми вызовами** |

Живой пример — от русского слова к документам:

```
saby_doc_types("счет")        -> СчетВх, СчетИсх, ФактураВх, ФактураИсх
saby_call("spisok_dokumentov", {"Фильтр": {"Тип": "СчетИсх"}})

  28.09.2026  №2467   2098400.00
  22.09.2026  №2463   2139775.53
  16.09.2026  №2462      9800.00
  ...
```

Требуют данных и потому не проверены:

| команда | что мешает |
|---|---|
| `СБИС.ИнформацияОКонтрагенте` | корень принят, но требует другой состав полей |
| `sabyMchd.GetStatus` / `GetContent` | на кабинете нет лицензии «МЧД API» |
| `СБИС.ПроверитьСертификаты`, `СБИС.ПрочитатьПриглашение` | корневой объект не установлен, помечены `verified: false` |

Непроверенные команды помечены явно, и сервер ничего не подставляет в их
`params` — иначе он гадал бы за пользователя и получал бы «метод не найден».

## Типы документов

Поле `Фильтр.Тип` принимает не название, а внутренний код типа из справочника
формата документов. Проверено живыми вызовами:

```
Тип="Счет"           -> «Указан неизвестный тип документа 'Счет'»
Тип="Счет на оплату" -> «Указан неизвестный тип документа 'Счет на оплату'»
Тип="СчетИсх"        -> работает
```

Человек думает «счёт», машина хочет `СчетИсх`. Без переводчика любая выборка
документов упирается в отказ, который выглядит как поломка сервера.

Поэтому в сервере есть `saby_doc_types` — перевод с человеческого на машинный:

```
saby_doc_types("счет")         -> СчетВх, СчетИсх, ФактураВх, ФактураИсх
saby_doc_types("накладная")    -> ConsignmentNote, ДокОтгрВх, ДокОтгрИсх
saby_doc_types("командировка") -> BusinessTrip, КорректировкаКомандировки
saby_doc_types(category="кадры")
```

59 типов из справки, 32 проверены настоящими вызовами на этой учётной записи.
Непроверенные не выдаются за рабочие.

Если тип всё же отвергнут, сервер не молчит, а перечисляет подходящие:

```
СБИС.СписокДокументов: Saby не знает тип документа 'Счет'.

Поле Фильтр.Тип принимает не название, а внутренний код типа...
Похожее на 'Счет':
  СчетВх    Счёт — Входящий
  СчетИсх   Счёт — Исходящий
  ...

Весь справочник (59 типов, 32 проверенных) — saby_doc_types.
```

Русские названия в справочник не попадают намеренно: они в нём означали бы
ровно то, что Saby отвергает.

## Почему «только чтение», а не «с подтверждением»

Подтверждение спрашивает человек, и это правильно для операции, которую он
понимает. Но у агента есть лучший повод остановиться: **не собирать такую
возможность вообще**.

Разница видна на конкретных примерах. У `СБИС.УдалитьДокумент` и
`СБИС.УничтожитьДокумент` в самой справке Saby разница в одну строку:

> «Удалить» помечает документ удалённым — вернуть можно.
> «Уничтожить» удаляет без возможности восстановления.

Сервер, который различает эти две команды, обязан различать их **правильно**.
Если в каталоге метка «удалить» стоит не там, ошибка необратима и не
проверяема: человек подтвердил «удалить», а потерял документ навсегда.
Отсутствие команды — единственная защита, которая не зависит от того, верно
ли расставлены метки.

## Вход

```bash
saby-mcp login
```

Спрашивает логин и пароль (пароль не печатается и не сохраняется) и кладёт
выданный Saby идентификатор сессии в `~/.saby-mcp/session.json` с правами 600.
Сессия живёт 21 день по умолчанию.

Если сессия уже есть, задайте её в `SBIS_SESSION_ID`.

### Почему вход отдельным шагом

`СБИС.Аутентифицировать` идёт на `https://online.sbis.ru/auth/service/` **без**
заголовка сессии — так она и выдаёт сессию. Если требовать `SBIS_SESSION_ID`
до входа, получается замкнутый круг: чтобы войти, нужна сессия.

## Подключение к ассистенту

### opencode

`~/.config/opencode/opencode.json`, секция `mcp.servers`:

```json
"saby": {
  "type": "local",
  "command": ["D:\\code\\sabyAgent\\.venv\\Scripts\\python.exe", "-m", "saby_mcp_ro"],
  "environment": { "SABY_MCP_HOME": "C:\\Users\\freej\\.saby-mcp" },
  "enabled": true
}
```

Пакет стоит в режиме `-e`, но **процесс MCP-сервера перезапускается вместе с
opencode** — правку в коде он подхватит только после перезапуска.

### Другие ассистенты

```json
{ "mcpServers": { "saby": { "command": "saby-mcp" } } }
```

## Инструменты

| инструмент | что делает |
|---|---|
| `saby_catalog` | карта разделов и команд |
| `saby_search` | найти команду словами, по-русски или по-английски |
| `saby_describe` | карточка: адрес, корневой объект params, форма результата, ссылка |
| `saby_call` | выполнить одну команду чтения |
| `saby_doc_types` | перевод «счёт» → `СчетИсх`: справочник типов документов |
| `saby_fetch_all` | получить строки списка |
| `saby_whoami` | проверить сессию и узнать, кто вошёл |

### Как это выглядит

```
Вы: список входящих за январь

saby_search("входящие документы")
  → СБИС.СписокДокументовПоСобытиям, СБИС.СписокДокументов, ...

saby_describe("spisok_dokumentov")
  → params_root: Фильтр
  → params: {"Фильтр": {"Тип": "…", "ДатаС": "01.01.2026", …}}
  → address: https://online.sbis.ru/service/?srv=1

saby_call("spisok_dokumentov", {"Фильтр": {"ТипРеестра": "Входящие",
                                           "ДатаС": "01.01.2026",
                                           "ДатаПо": "31.01.2026"}})
```

Агент передаёт только `params`. Конверт JSON-RPC — `jsonrpc`, `method`, `id`,
вложенный `params` — собирает сервер из записи каталога.

## Транспорт Saby: что выяснилось на живом контуре

У Saby один адрес и тело, где лежит имя команды. Три вещи здесь ломают
наивные реализации, и все три проверены настоящими вызовами.

**1. Команде нужен её корневой объект в `params`.**
Пустые `params` дают `-32601` «метод не найден» — хотя команда есть и названа
верно. Выглядит как поломка сервера, хотя не разобрались именно параметры:

| команда | корень |
|---|---|
| `СБИС.СписокДокументов`, `СписокЗадач`, `СписокИзменений`, `СписокНашихОрганизаций` | `Фильтр` |
| `СБИС.ИнформацияОТекущемПользователе`, `СписокПодразделений`, `ИнформацияОВерсии` | `Параметр` |
| `СБИС.ПрочитатьДокумент` | `Документ` |
| `sabyMchd.GetStatus` | `MchdNumber` |
| `sabyDepartment.Read` | `departments` |
| `СБИС.СписокАккаунтов` | пустые `params` |
| `СБИС.Аутентифицировать` | `Параметр` |

Сервер подставляет пустой корень сам, если агент его не передал.

**2. Адрес и заголовок сессии — независимые признаки.**

| команда | адрес | сессия |
|---|---|---|
| `СБИС.Аутентифицировать` | `/auth/service/` | не нужна |
| `СБИС.СписокАккаунтов` | `/auth/service/` | **нужна** |
| `СБИС.ИнформацияОТекущемПользователе` | `/service/?srv=1` | нужна |

Когда сессия выводилась из адреса, первые две команды ходили не туда.

**3. `Content-Type` обязан содержать `charset`.**
`application/json` без `charset=utf-8` даёт `-32700`, сервер не может разобрать
тело. С `charset` — работает.

## Пагинация: сервер не даёт её использовать

Это ограничение Saby, а не недоработка сервера.

Справка описывает объект `Навигация` как способ навигации, но **на живом
контуре он не принимается в запросе** — ни с `РазмерСтраницы`, ни с
`Позиция.ДатаВремя`, ни пустой `{}`. Ответ во всех случаях один:
`-32601` «метод не найден». Продвижение через `Фильтр.ИдентификаторСобытия`
тоже отклоняется (`-32000`).

Без `Навигации` сервер отдаёт первую порцию сам и сообщает в ответе:

```json
"Навигация": {"ЕстьЕще": "Да", "РазмерСтраницы": "25"}
```

Поэтому `saby_fetch_all` возвращает одну порцию и, если `ЕстьЕще = Да`,
**прямо пишет об усечении в `notes`**. Молча отдать 25 строк из 300 значило бы
сказать человеку «это все документы».

Рабочий способ обойти усечение — сузить период или тип в фильтре.

## Как устроено ограничение на запись

Защита не в одном месте, а в четырёх, и каждого слоя достаточно:

1. **Каталог** содержит только команды чтения — значит, нет и в `BY_COMMAND`,
   по которому идёт любой вызов.
2. **Нет инструмента с адресом.** Ни один не принимает `url`, `host`, `path`
   или `method`. Сырых инструментов (`get_raw`/`write_raw`/`delete_raw`) нет.
3. **Проверка перед отправкой** (`client._check_allowed`) сверяет имя команды
   с каталогом последним шагом, уже перед HTTP-запросом.
4. **Тест ловит попытку** — двенадцать команд записи, зная их настоящие имена,
   и требует, чтобы ни один запрос не ушёл.

```
ОТКАЗ  СБИС.ЗаписатьДокумент      ОТКАЗ  sabyDepartment.Delete
ОТКАЗ  СБИС.УдалитьДокумент       ОТКАЗ  sabyOurCompany.Create
ОТКАЗ  СБИС.УничтожитьДокумент   ОТКАЗ  СБИС.ПодписатьВложение

Запросов на провод: 0
```

## Тесты

```bash
python -m pytest -q     # 260 тестов, сеть не нужна
```

Тесты не ходят в сеть: `httpx.AsyncClient` подменяется заглушкой, которая
записывает запросы. Проверить, что ушло на провод и с каким телом, можно не
выходя из тестов.

Часть помечена `regression` — ошибки, найденные в существующем сервере
`sbis-mcp-ru` и в моём собственном коде при сверке с живым контуром:

| ошибка | как закрыто |
|---|---|
| имя команды не подставлялось в тело запроса | `build_envelope` — единственное место сборки тела |
| команды auth на `/service/` вместо `/auth/service/` | `endpoint` в каталоге |
| вход невозможен без уже имеющейся сессии | `client.login` идёт без заголовка |
| сессия выводилась из адреса | `needs_session` — отдельное поле |
| без корневого объекта всё отвечает «метод не найден» | `catalog.with_root` |
| `items_path` не задан | `result_key` у каждой команды |
| `СписокИзмененийПриглашений` отдаёт не под тем ключом | `result_key` подтверждён живьём |
| `Навигация` в запросе ломает команды | не отправляется, усечение раскрывается честно |
| `limit`/`offset` в корне конверта вместо `params` | `build_envelope` |
| `operation_id` в латинице не сходился с русским запросом | в индекс не входит |
| `doctor --live` всегда `skipped` | есть whoami-команда |
| три инструмента давали произвольный путь | их нет |
| ошибка входа звала несуществующий инструмент `saby_login` | вход из терминала |

## Границы

Честно о том, что не проверено и не сделано.

- **Документы по типам** работают — нужен перевод, который делает
  `saby_doc_types`. Словарь неполон: 27 типов из справочки не проверены на этой
  учётной записи, и среди них `Док` (договор) и `АктСверки`, которые кабинет
  отверг. Новые типы в справочник добавляются по мере надобности.
- **`СБИС.ИнформацияОКонтрагенте`** принимает корень `СвЮЛ`, но отвечает
  `-32602`: нужен другой состав полей. Форма не установлена.
- **Три команды без установленной структуры params** помечены
  `verified: false`. Сервер ничего в них не подставляет.
- **МЧД** требует лицензии «МЧД API» на кабинете. Без неё отказ по данным,
  а не ошибка кода.
- **Пагинация недоступна** — см. раздел выше. Это ограничение контура.
- **Двухфакторная аутентификация** не поддержана: `СБИС.ПодтвердитьВход`
  пишет, а писать мы не умеем.
- **Типы внутренних полей не валидируются.** Схем у Saby нет; в каталоге
  лежит подсказка для агента. Ошибку поймает Saby и вернёт текст, который
  сервер покажет как есть.
