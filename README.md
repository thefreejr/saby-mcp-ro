# saby-mcp-ro

MCP-сервер, который даёт ИИ-ассистенту **читать** данные из Saby (СБИС):
документы, задачи, контрагентов, организации, сертификаты.

Он не умеет ничего менять. Команды записи и удаления не заблокированы
и не спрятаны — их просто нет в коде. Подробнее ниже, в разделе
[«Почему нельзя записать»](#почему-нельзя-записать).

---

## Быстрый старт

Три шага, от чистой машины до работающего сервера.

### 1. Установить

```bash
pip install -e .
```

### 2. Войти в Saby

```bash
saby-mcp login
```

Спрашивает логин и пароль, пароль не печатается и нигде не сохраняется.
Выданный идентификатор сессии кладёт в `~/.saby-mcp/session.json` с правами
только для вас. Сессия живёт 21 день.

Проверить, что вошли:

```bash
saby-mcp doctor --live
```

Должно быть `ок — вошли как <Фамилия Имя Отчество>`.

Если сессия уже есть, можно положить её в переменную `SBIS_SESSION_ID`
и не входить вовсе.

### 4. Посмотреть сводку

```bash
saby-mcp digest
```

Сразу после входа — без настройки, без расписания. Подробности ниже.

### 3. Подключить к ассистенту

Для opencode — в `~/.config/opencode/opencode.json`:

```json
"saby": {
  "type": "local",
  "command": ["D:\\путь\\к\\проекту\\.venv\\Scripts\\python.exe", "-m", "saby_mcp_ro"],
  "environment": { "SABY_MCP_HOME": "C:\\Users\\вы\\.saby-mcp" },
  "enabled": true
}
```

Для других ассистентов:

```json
{ "mcpServers": { "saby": { "command": "saby-mcp" } } }
```

Отвечайте на «покажи счета за сентябрь» — ассистент сам найдёт нужную
команду и вызовет её. На «что входящего» ответит `saby_digest`.

## Девять инструментов

| инструмент | что делает | когда нужен |
|---|---|---|
| `saby_digest` | **сводка входящих**: что пришло, что висит, что изменилось | «что входящего», «сводка за вчера», «что нового» |
| `saby_search` | ищет команду по словам, по-русски или по-английски | «не знаю, какая команда это делает» |
| `saby_describe` | карточка команды: какие параметры, какой адрес, какая ссылка на справку | перед вызовом |
| `saby_call` | выполняет одну команду | почти всегда |
| `saby_fetch_all` | достаёт строки списка | когда нужен именно список |
| `saby_doc_types` | переводит «счёт» → `СчетИсх` | **перед любой выборкой документов** |
| `saby_catalog` | карта разделов и всех команд | когда хочется просто посмотреть, что есть |
| `saby_whoami` | кто вошёл и жива ли сессия | для проверки |
| `saby_digest_cursor` | где остановилась прошлая сводка, сброс курсора | «с какого момента смотрим» |

Обычный разговор выглядит так:

```
Вы: покажи входящие за октябрь

saby_search("входящие документы за период")
  → СБИС.СписокДокументовПоСобытиям

saby_describe("spisok_dokumentov_po_sobytiyam")
  → нужно поле Фильтр.ТипРеестра и ещё что делать

saby_call("spisok_dokumentov_po_sobytiyam", {"Фильтр": {
      "ТипРеестра": "Входящие",
      "ДатаС": "01.10.2026",
      "ДатаПо": "31.10.2026"}})
```

Ассистент передаёт серверу только `params`. Конверт JSON-RPC — `jsonrpc`,
`method`, `id`, вложенный `params` — сервер собирает сам из карточки команды.

## Сводка входящих

На вопросы «что входящего», «что нового», «сводка за вчера», «что изменилось
с утра» отвечает `saby_digest` — одним вызовом вместо двадцати. То же самое
из терминала:

```bash
saby-mcp digest                      # за вчера и сутки
saby-mcp digest --days 7             # за неделю
saby-mcp digest --since 01.10.2026 --until 12.10.2026
saby-mcp digest --save               # запомнить конец окна как курсор
saby-mcp digest --reset              # забыть курсор
saby-mcp digest --json               # целиком, не только текст
```

```
Сводка входящих · 13.10.2026 (с 12.10.2026 00.00.00)

Пришло событий: 2 (документов: 2)
 ! 12.10.2026 17.39.53  Договор № 191 от 20.07.2026 · Т2 Мобайл, ООО — Ожидает аннулирования
   12.10.2026 14.50.12  Счет № 41079 от 12.10.2026 на сумму 2603.00 · Аврора-К, ООО

Требует внимания: 5 задач на мне, самый старый — 211 дн.
  · Договор № 8957 от 16.03.2026 — В обработке (211 дн. в работе)
  · Договор № 1684 от 18.06.2026 — Выполнение завершено с проблемами (117 дн. в работе)

Изменилось с прошлого раза: 92 события по 38 документам

Необработанных служебных этапов: 0
```

Четыре источника, все — команды каталога: реестр «Входящие», список задач
«На мне», список изменений, счётчик служебных этапов.

### Почему это нельзя было собрать «просто пятью вызовами»

Всё ниже проверено живыми вызовами на рабочей сессии.

**Ответ реестра нечитаем.** 25 событий весят **209 КБ**, и восемь девятых —
это `СсылкаНаPDF` (base64) и `СсылкаНаАрхив` в каждом документе и в каждом
вложении. Сводка оставляет около двадцати полей на документ, а ссылку в
кабинет добавляет только по запросу (`with_links=True`, `--links`).

**Порция в 25 строк обходится.** Объект `Навигация` работает, но вариант
у него не один, и способ листать зависит от команды. Разбирали на живых
вызовах, 15–16.10.2026:

| Команда | Чем листает | Потолок страницы |
|---|---|---|
| `СписокДокументовПоСобытиям`, `СписокДокументов`, `СписокНашихОрганизаций`, `СписокСлужебныхЭтапов` | `Навигация.Страница`, номер с нуля | 200 (у служебных этапов — 20) |
| `СписокЗадач` | `Навигация.Позиция.ДатаВремя` из `Навигация.СледующаяПозиция.ДатаВремя` | 50 |
| `СписокИзменений` | `Фильтр.ИдентификаторСобытия` + `ДатаВремяС`, поля `Страница` у него нет | 200 по факту, 50 в справке |
| `СписокИзмененийПриглашений` | ничем: курсор документирован, но выдачу не двигает | 200 |

`Навигация` должна быть **внутри** `Фильтр`: в корне параметров объект
игнорируется и ответ приходит пустым. Команды без корневого объекта
(`СписокАккаунтов`, `СписокПодразделений`) навигацию не принимают вовсе.

Три ошибки подряд выросли из одного: каждую проверяли на `СписокИзменений`
или на недокументированном поле — то есть на команде, где нужного поля нет.
Прежде чем судить о возможностях Saby, стоит прочитать страницу нужной
команды целиком и проверить на той, где поле документировано.

Замеры: реестр за месяц при порции 25 — 6 страниц и 140 строк; изменения за
двое суток — 11 страниц и 260 событий. Сверка обхода с выдачей по 200 строк:
те же 260 событий, ни одного потерянного и лишнего.

**Окно реестра — по дате события, а не документа.** За 12.10 пришло событие
по договору от 20.07. Для сводки это верное поведение, но заметить надо:
если курсор стоит на 06:00, а реестр отдаёт сутки с полуночи, остаток
окна дорезается по времени события.

**Дубли — норма.** «На мне» отдаёт 9 строк на 8 документов, список изменений
присылает один документ дважды. Дедупликация по идентификатору и по паре
«документ + событие» — внутри сводки.

**Фильтр по сотруднику в задачах не работает.** `Фильтр.Сотрудник` вернул
те же 9 строк, включая задачи Шаймуллиной и Гусева. Сводка его не отправляет
вовсе: чужие задачи показывать нельзя, а тихо отбрасывать их — значит врать.

**`Срок` пуст почти всегда:** у 24 событий из 25 и у 8 задач из 9. Просрочка
считается только там, где срок заполнен, а возраст в работе — от
`ДатаВремяСоздания`.

**`ТипВложения` в реестре отдаёт пустоту.** Запрос с `ТипВложения="СчетВх"`
вернул 0 строк вместо 13 счетов. Делить переполненный день по типу нельзя:
получилась бы видимость полноты вместо самой полноты. Делим по состояниям —
этот фильтр на живой сессии работает.

**Валюту Saby не отдаёт.** В ответе есть `Сумма` и `СуммаБезНДС`, но не
валюта. Угадывать её в сводке нельзя, поэтому сумма выводится как есть.

### Курсор

`saby_digest` помнит, где остановился, в `~/.saby-mcp/digest-state.json`
(рядом с сессией, перекрывается `SABY_MCP_HOME`). Следующий запуск берёт
изменения ровно с этого места — это и есть режим «что изменилось с утра».

**Курсор двигается только по полному ответу.** Если выдача оказалась
усечённой, он остаётся на месте: сдвинуть его вперёд — значило бы потерять
хвост навсегда. Лучше повторный день в сводке, чем пропавший.

Курсор двигается только при `save_cursor: true` (инструмент) или `--save`
(терминал). Ни то, ни другое в Saby ничего не пишет — файл локальный.

### Когда усечение остаётся

На 12 октября есть двенадцать минут, в которые событий больше порции в 25
строк (массовая выгрузка документов). Дальше дробить некуда: Saby отдаёт по
25 строк и не даёт курсор. Сводка в таком случае пишет, в какое именно окно
неполно, и курсор не двигает — это единственный честный вариант.

## Три места, где спотыкаются

Это ограничения самого Saby. Обойти их нельзя, но сервер умеет объяснить,
что произошло, — и вам, и ассистенту.

### Тип документа: не название, а код

Поле `Фильтр.Тип` ждёт внутренний код из справочника Saby, а не то, что
написано на бумаге:

```
Тип="Счет"           → «Указан неизвестный тип документа 'Счет'»
Тип="Счет на оплату" → «Указан неизвестный тип документа 'Счет на оплату'»
Тип="СчетИсх"        → работает
```

Человек думает «счёт», машина хочет `СчетИсх`. Отказ выглядит как поломка
сервера, хотя сервер здесь ни при чём.

Поэтому сначала спросите `saby_doc_types`:

```
saby_doc_types("счет")         → СчетВх, СчетИсх, ФактураВх, ФактураИсх
saby_doc_types("накладная")    → ConsignmentNote, ДокОтгрВх, ДокОтгрИсх
saby_doc_types("командировка") → BusinessTrip, КорректировкаКомандировки
```

Если тип всё-таки отвергнут, сервер не молчит — перечисляет похожие:

```
СБИС.СписокДокументов: Saby не знает тип документа 'Счет'.

Поле Фильтр.Тип принимает не название, а внутренний код типа...
Похожее на 'Счет':
  СчетВх    Счёт — Входящий
  СчетИсх   Счёт — Исходящий

Весь справочник — saby_doc_types.
```

В справочнике 59 типов из справки Saby, 32 проверены настоящими вызовами на
рабочей учётной записи. Русские названия в него не входят намеренно: они
означали бы ровно то, что Saby отвергает.

### Страницы

Saby отдаёт 25 строк и сообщает, что есть ещё. Обойтись можно так:

```json
"Навигация": {"РазмерСтраницы": "200", "Страница": "0"}
```

`Страница` — номер страницы с нуля, и она есть не у всех команд (таблица
выше). Размер страницы задаётся той же `Навигацией`, потолок свой у каждой
команды. Для постраничной выборки по времени работает пара
`Фильтр.ИдентификаторСобытия` + `Фильтр.ДатаВремяС`, и туда кладётся
**`Событие.Идентификатор`** последнего события, а не `Документ.Идентификатор`
— с идентификатором документа сервер отвечает иначе.

`saby_fetch_all` обходит страницы сам, выбирая способ по команде, и в ответе
отдаёт `pages_fetched`. Если обход упёрся, в `notes` написано почему.

**Про организацию.** Если в кабинете несколько организаций, без явного отбора
Saby отдаёт смесь по всем сразу. Задать свою можно в `config.json` рядом с
сессией:

```json
{ "наша_организация": { "СвЮЛ": { "ИНН": "1615013278", "КПП": "165501001" } } }
```

Переменная `SABY_OUR_ORGANIZATION` перекрывает файл. Отбор подставляется
только в те команды, где поле документировано, и заданный вызывающим не
перебивается.

**Что делать:** сузить период или тип в фильтре. Документы за месяц
одного контрагента обычно умещаются в одну порцию. Сводка входящих
(`saby_digest`) делает это сама — см. раздел выше.

## Почему нельзя записать

Подтверждение «точно удалить?» — правильная идея, но для агента есть вариант
лучше: **не собирать такую возможность вообще**.

В справке Saby есть две команды, которые различаются одной строкой:

> **Удалить** — помечает документ удалённым, вернуть можно.
> **Уничтожить** — удаляет без возможности восстановления.

Сервер, который умеет и то и другое, обязан различать их **правильно**.
Стоит метка «удалить» не на той команде — и человек подтвердил «удалить»,
а потерял документ навсегда. Ни ошибку, ни подтверждение это не спасут:
решение уже принято, документ уже стёрт.

Отсутствие команды — единственная защита, которая не зависит от того,
верно ли расставлены метки.

### Как это сделано

Защита не в одном месте, а в четырёх, и каждого слоя достаточно:

1. **В каталоге только чтение.** Любой вызов идёт по таблице команд, значит
   команды записи в ней нет.
2. **Ни один инструмент не принимает адрес.** Ни параметра `url`, ни `host`,
   ни `path`, ни `method`. Обратиться куда попало нечем. Сырых инструментов
   (`get_raw` / `write_raw` / `delete_raw`) в проекте нет.
3. **Проверка перед отправкой.** `client._check_allowed` сверяет имя команды с
   каталогом последним шагом, уже перед HTTP-запросом — даже если команда
   как-то просочилась в инструмент.
4. **Тест ловит попытку.** Двенадцать команд записи по их настоящим именам,
   после чего требуется, чтобы ни один запрос не ушёл на провод.

```
ОТКАЗ  СБИС.ЗаписатьДокумент      ОТКАЗ  sabyDepartment.Delete
ОТКАЗ  СБИС.УдалитьДокумент       ОТКАЗ  sabyOurCompany.Create
ОТКАЗ  СБИС.УничтожитьДокумент   ОТКАЗ  СБИС.ПодписатьВложение

Запросов на провод: 0
```

## Для тех, кто будет править код

### Транспорт Saby: три вещи, которые ломают наивные реализации

У Saby один адрес и тело запроса, где лежит имя команды. Все три грабли ниже
наступают одинаково — выглядят как «сервер сломался», хотя сломался код.

**1. Команде нужен её корневой объект в `params`.**
Пустые `params` дают `-32601` «метод не найден» — хотя команда существует и
названа верно. Не разобрались именно параметры, а не имя.

| команда | корень |
|---|---|
| СписокДокументов, СписокЗадач, СписокИзменений, СписокНашихОрганизаций | `Фильтр` |
| ИнформацияОТекущемПользователе, СписокПодразделений, ИнформацияОВерсии | `Параметр` |
| ПрочитатьДокумент | `Документ` |
| sabyMchd.GetStatus | `MchdNumber` |
| sabyDepartment.Read | `departments` |
| СписокАккаунтов | пустые `params` |

Сервер подставляет пустой корень сам, если агент его не передал.

**2. Адрес и заголовок сессии — независимые признаки.**

| команда | адрес | сессия |
|---|---|---|
| `СБИС.Аутентифицировать` | `/auth/service/` | не нужна |
| `СБИС.СписокАккаунтов` | `/auth/service/` | **нужна** |
| `СБИС.ИнформацияОТекущемПользователе` | `/service/?srv=1` | нужна |

Когда сессия выводилась из адреса, первые две команды ходили не туда.
Сейчас `endpoint` и `needs_session` — отдельные поля карточки команды.

**3. `Content-Type` обязан содержать `charset`.**
`application/json` без `charset=utf-8` даёт `-32700`: Saby не может разобрать
тело. С `charset` — работает.

Ещё одно, менее очевидное: **`СБИС.ПрочитатьДокумент` возвращает сам
документ верхним уровнем `result`** — поля `Название`, `Контрагент`,
`Вложение`, `Событие` лежат прямо в ответе, без обёртки `Документ`. Ошибка
здесь молча даёт пустоту: вызов успешен, а извлекать нечего.

### Почему вход отдельной командой

`СБИС.Аутентифицировать` идёт на `/auth/service/` **без** заголовка сессии —
так она и выдаёт сессию. Если требовать `SBIS_SESSION_ID` до входа,
получается замкнутый круг: чтобы войти, нужна сессия.

### Сводка: обход порции рекурсией, а не курсором Saby

Курсора у Saby нет, поэтому окно делится пополам до дроби, меньше которой
Saby всё равно вернёт те же 25 строк. Рекурсия спускается **только туда,
где порция действительно кончилась**: тихий день — один вызов, загруженный —
десяток.

```python
rows, complete = ask(0, minutes)      # окно целиком
if complete: return rows, True       # тихий день — всё
middle = first + (last - first) // 2  # иначе пополам
left  = await walk(first, middle)
right = await walk(middle, last)
```

Потолок — `digest.MAX_CALLS` вызовов на всю сводку. Он срабатывает не как
ошибка, а как граница: окно, до которого дошли, попадает в сводку целиком,
недошедшее — в `notes` с точным временем. `_BudgetSpent` прерывает рекурсию
снаружи, а не молча возвращает пустоту.

### Файлы состояния

`session.json` и `digest-state.json` пишет один и тот же код — `JsonStore`
(`jsonstore.py`): атомарная запись через `mkstemp` + `os.replace`, права 600,
терпимость к битому JSON. Два писателя в один файл означали бы два места,
где «просто запишем», а падение посреди записи там стоило бы живой сессии.

### Тесты

```bash
python -m pytest -q     # 309 тестов, сеть не нужна
```

Тесты не ходят в сеть: `httpx.AsyncClient` подменяется заглушкой, которая
записывает запросы. Можно проверить, что ушло на провод и с каким телом,
не выходя из тестов.

Часть тестов помечена `regression` — они закрывают ошибки, найденные при

## Границы

Что не проверено и не сделано — чтобы не было сюрпризов.

- **Пагинации нет.** Ограничение Saby, не сервера. См. выше. В сводке
  обходится окнами; усечение, которое разбить нельзя, раскрывается честно.
- **Есть окна, где усечение не лечится.** На 12 октября нашлись двенадцать
  минут с числом событий больше порции. Дальше дробить некуда, и сводка
  пишет об этом прямо.
- **`СБИС.ИнформацияОКонтрагенте`** принимает корень `СвЮЛ`, но отвечает
  `-32602`: нужен другой состав полей. Форма не установлена, команда
  помечена непроверенной.
- **Три команды без установленной структуры params** — `ПрочитатьПриглашение`,
  `ПроверитьСертификаты`, `sabyMchd.GetContent` — помечены `verified: false`.
  Сервер ничего в них не подставляет, чтобы не гадать за пользователя.
- **МЧД** требует лицензии «МЧД API» на кабинете. Без неё отказ по данным,
  а не ошибка кода.
- **Двухфакторная аутентификация** не поддержана: подтверждение входа
  записывает данные, а писать мы не умеем.
- **Словарь типов неполон:** 27 типов из 59 не проверены на этой учётной
  записи. Новые добавляются по мере надобности.
- **Внутренние типы полей не валидируются.** Схем у Saby нет, поэтому в
  карточке команды лежит подсказка для ассистента, а проверяет сам Saby и
  возвращает текст, который сервер показывает как есть.
- **Правка в коде подхватывается только после перезапуска opencode.**
  Процесс MCP-сервера запускается вместе с ассистентом.

Проверено живыми вызовами на боевой сессии: 22 команды в каталоге, 15
вернули данные, 7 требуют настоящих данных или лицензии. Сводка входящих
проверена на той же сессии: за двое суток — 2 входящих события, 8 задач на
месте, 92 изменения по 38 документам, 0 служебных этапов, 24 вызова.
Падений, ошибок и зависаний — ноль.
